# Панель tg-panel — работа с ноутбука

Эта папка — копия кода с сервера, данные сервера — копией в `server-data/`
(`./tg data`; `.env`, сессии, реестр, база, лиды, второй профиль). Хозяин — CTO
проекта, ему можно всё. Сервер — живая рассылка по Telegram: два десятка
аккаунтов греются и пишут людям прямо сейчас.

## Цикл работы и связь с сервером

Агенту (тебе) нужен VPN. Сервер адрес VPN не пускает, поэтому у хозяина может
быть настроен обход: `./tg bypass` — трафик к серверу идёт мимо VPN. Связь
проверяй так: `ssh -o ConnectTimeout=8 tg-server true`.
- Связи нет — `./tg pull|ship|status|data|logs|undo|restart` и `ssh tg-server`
  не запускай: попроси хозяина нажать кнопку в пульте и прислать вывод.
- Связь есть — журнал и состояние сервера смотри сам (`./tg logs 200`,
  `ssh tg-server '…'`); выкладывай (`./tg ship`) только когда хозяин просит или
  идёт ночная смена (пульт пришлёт задание «НОЧНАЯ СМЕНА» со своими правилами).

- Правишь файлы тут. Проверяешь локально: `./tg test` (обогащение, один раз до
  этого хозяин делает `./tg venv`), `node --check <файл>`,
  `python3 -m py_compile <файл>`.
- Хозяин работает с тобой через пульт в браузере (`./ai`): справа у него кнопки
  «Выложить», «Забрать код», «Журнал панели», «Обновить данные», «Откатить».
- Менял файлы и сам не выложил — коротко скажи, что поменял и что будет на
  сервере, и последней строкой: «Готово к выкладке: нажми «Выложить»» (в
  терминале — `./tg ship`). Только читал или отвечал — этой строки не пиши.
  Коммитить не нужно: выкладка сама закоммитит и вольёт свежие правки с сервера.
- Как работает ship: уезжают только файлы, которые отличаются от сервера;
  правка `.py` и страниц действует со следующего запуска задачи, без
  перезапуска; при правке `*.mjs` панель перезапустится, когда никто не пишет
  людям; Python и node сервера проверяют код до замены файлов. `./tg undo` —
  вернуть файлы до последней выкладки. `--force` у ship обрывает рассылку —
  только с прямого согласия хозяина.
- Ночная смена: работаешь сам до утра, без вопросов; журнал смены —
  `docs/NIGHT.md` (обновляй после каждого шага, перечитывай, если потерял нить);
  после каждой выкладки — `./tg logs 80` и `ssh tg-server 'systemctl is-active
  tg-panel'`, сломалось — сразу `./tg undo`. Конец — итог в журнале и строка
  «МИССИЯ ВЫПОЛНЕНА»; без человека никак — строка «НУЖЕН ЧЕЛОВЕК».
- Проверка «Лидов» вживую — через панель на сервере (http://127.0.0.1:8787,
  `ssh tg-server curl …`), вход — `POST /api/login` с логином и паролем из
  `~/.tg-agent/panel.json` (значения не печатай); действия — `grep "/api/enrich/"
  admin.mjs`. Telegram-задачи в обход панели не запускай: тот же аккаунт из двух
  мест Telegram выкидывает.
- Данные сервера — в `server-data/` (обновляет хозяин: `./tg data`). Посмотри
  там, прежде чем просить команду.
- В начале новой задачи, если хозяин давно не забирал код, напомни:
  `./tg pull` (без VPN) — владелец сервера иногда правит код прямо там.
- git тут локальный, без GitHub: `main` — работа, `server` — снимки сервера.
  Никуда не пушь, remote не добавляй. Конфликт после pull или ship — разреши
  слиянием (оставь и правку владельца, и нашу), закоммить; хозяин повторит команду.

## Сервер — `ssh tg-server`

- root@46.16.15.238. Код и данные основного профиля — `/opt/tg-panel`, второй
  профиль — `/opt/tg-panel/profiles/vtoroy`. Служба `tg-panel`, пользователь
  `tgpanel`. Панель — https://bqa.egor-kochnev.ru. Python 3.14 и Telethon 1.45
  в `venv-tg`, Node 20.
- Смотреть можно: логи, `ps`, файлы данных (кроме секретов). Менять что-то на
  сервере руками, запускать задачи, трогать данные — только с согласия хозяина.
  Код меняем здесь и выкладываем через `./tg ship`, не правкой на сервере.
- Python-задачу руками — только так, иначе в папке появятся файлы root, и
  панель не сможет их писать:
  `cd /opt/tg-panel && runuser -u tgpanel -- env TG_PANEL_DIR=/opt/tg-panel venv-tg/bin/python <скрипт>`
- `server-data/` — копия только для чтения. Не запускай с ней задачи и не
  ходи с этими сессиями в Telegram с ноутбука: один ключ сразу из двух мест
  Telegram отзывает (AUTH_KEY_DUPLICATED) — аккаунт вылетает и на сервере.
  Данные правятся на сервере (с согласия хозяина), с ноутбука их не возим.
- Значения ключей, паролей и токенов в ответах не печатай — маскируй
  (`sk-or-…a1b2`): переписка уходит в API. Нужно проверить ключ — проверь,
  что он есть и работает, а не показывай его.
- Перезапускать службу — только через `./tg`; удалять данные — только по прямой
  просьбе хозяина.

## Как устроен код

- `docs/CODE.md` — устройство панели; `docs/HANDOVER.md` — где что лежит;
  `docs/NEXT.md` — где остановились, читать первым при задаче по «Лидам».
- Панель сама в Telegram не ходит: `admin.mjs` запускает Python-задачи по одной
  на аккаунт и читает их вывод; последняя строка задачи — `⌁STATE {json}`.
- Большие файлы (`admin.mjs`, `web/app.js` — тысячи строк) читай кусками:
  grep, потом нужный диапазон строк.

## Как работать

- Работа идёт за деньги хозяина (API). Не читай файлы целиком без нужды, не
  запускай субагентов ради того, что делается парой команд.
- Отвечай по-русски, коротко. Только короткое тире «-». Английский термин —
  сразу с переводом.
- Не уверен, что правка безопасна для живой рассылки, — спроси, а не выкладывай.
