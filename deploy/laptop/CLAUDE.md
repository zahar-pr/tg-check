# Панель tg-panel — работа с ноутбука

Эта папка — копия кода с сервера (без данных и секретов). Сервер — живая
рассылка по Telegram: два десятка аккаунтов греются и пишут людям прямо сейчас.

## Цикл работы

- В начале работы — `./tg pull`: владелец иногда правит код прямо на сервере.
- Правишь файлы тут. Обогащение («Лиды») проверяй тестами: `./tg test`
  (один раз до этого — `./tg venv`).
- Выложить — `./tg ship`. Уезжают только файлы, которые отличаются от сервера.
  Правка `.py` и страниц действует со следующего запуска задачи, без перезапуска;
  при правке `*.mjs` панель перезапустится, когда никто не пишет людям.
  Python и node сервера проверяют код до замены файлов.
- Выкладывай, когда хозяин просит («выложи», «залей») или согласился. Перед
  этим одной строкой скажи, что уедет. После — проверь `./tg logs 100`.
- `./tg undo` — вернуть файлы до последней выкладки. `./tg status` — что
  отличается. `--force` у ship/restart обрывает рассылку — только с прямого
  согласия хозяина.
- git тут локальный, без GitHub: `main` — работа, `server` — снимки сервера.
  Никуда не пушь, remote не добавляй. Конфликт после pull/ship — разреши
  слиянием (оставь и правку владельца, и нашу), закоммить, повтори команду.

## Как устроен код

- `docs/CODE.md` — устройство панели; `docs/HANDOVER.md` — где что лежит;
  `docs/NEXT.md` — где остановились, читать первым при задаче по «Лидам».
- Панель сама в Telegram не ходит: `admin.mjs` запускает Python-задачи по одной
  на аккаунт и читает их вывод; последняя строка задачи — `⌁STATE {json}`.
- Большие файлы (`admin.mjs`, `web/app.js` — тысячи строк) читай кусками:
  grep, потом нужный диапазон строк.

## Как работать

- Работа идёт за деньги хозяина (API). Не читай файлы целиком без нужды, не
  запускай субагентов ради того, что делается парой команд.
- Отвечай по-русски, коротко. Только короткое тире «-». Английский термин —
  сразу с переводом.
- Не уверен, что правка безопасна для живой рассылки, — спроси, а не выкладывай.
