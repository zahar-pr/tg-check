# Передача проекта

Документ для того, кто принимает работу. Здесь — что это за система, где она
живёт, как в неё попасть, где лежат секреты и что трогать осторожно.

**Секретов в этом файле нет** — только адреса, где они хранятся, и команды,
которыми их прочитать. Репозиторий на GitHub, класть туда пароли нельзя.

---

## 1. Что это

Веб-панель для работы с пулом Telegram-аккаунтов: подключение сессий, прогрев
поведением, проверка базы номеров, рассылка первых и вторых писем, разбор
чатов.

Бэкенд — Node (без фреймворков), вся работа с Telegram — Python-задачи на
Telethon. Фронтенд — три файла без сборки: `web/index.html`, `app.js`, `app.css`.

Главное, что стоит понять с самого начала: **панель не ходит в Telegram сама**.
Она запускает Python-скрипты по одному на аккаунт и читает их вывод построчно.
Последняя строка задачи — `⌁STATE {json}` — это её отчёт автоматике: сколько
сделано, сколько осталось, не придержал ли Telegram аккаунт и на сколько.

## 3. Профили — несколько независимых панелей в одной

Привратник `router.mjs` занимает порт 8787 и держит по процессу `admin.mjs`
на каждый профиль (внутренние порты 8801, 8802, …). Вошёл своим логином —
попал в свой профиль; чужого для тебя не существует.

У профиля своя папка с данными: реестр аккаунтов, сессии, база, результаты,
прогрев, тексты писем. Код общий на всех — обновление одно.

| Профиль | Папка данных |
|---|---|
| Основной | `/opt/tg-panel` |
| Второй | `/opt/tg-panel/profiles/vtoroy` |

Управление — вкладка «Профили» у основного профиля, либо командой:

```bash
cd /opt/tg-panel && sudo -u tgpanel node profiles.mjs список
sudo -u tgpanel node profiles.mjs завести <имя> "<название>" <логин> <пароль>
```

Папку данных задаёт переменная `TG_PANEL_DIR` — её выставляет привратник.
Любой скрипт можно запустить руками для нужного профиля:

```bash
sudo -u tgpanel env TG_PANEL_DIR=/opt/tg-panel/profiles/vtoroy \
  venv-tg/bin/python stats.py --account a1
```

### Как панель запускает задачи

`run()` в `admin.mjs` порождает процесс, пишет его вывод в журнал панели и в
ленту событий, а строку `⌁STATE` забирает себе. Поля отчёта:

* `done` / `left` — сколько сделано и осталось;
* `stop` — `flood` (Telegram придержал), `quota` (кончилась квота контактов),
  `quarantine` (ограничение SpamBot), `errors`;
* `cooldown` — сколько секунд аккаунту отдыхать;
* `note`, `act`, `phase` — человеческие подписи для панели.

## 6. Где лежат секреты

Ни одного пароля в репозитории нет. Вот где они на сервере:

| Что | Где лежит | Как прочитать |
|---|---|---|
| Вход в панель (хэш) | `<профиль>/auth.json` | пароль не восстановить, можно задать новый: `node set-password.mjs` |
| Вход во второй профиль | `/root/profil-vtoroy.creds` | `cat /root/profil-vtoroy.creds` |
| Пароль мобильного прокси | `<профиль>/accounts.json`, поле `proxy` | `grep -o '"proxy":"[^"]*"' accounts.json \| sort -u` |
| Ссылка смены IP прокси | `<профиль>/warmup.json`, поле `rotate` | содержит ключ провайдера |
| Ключ LLM | `/opt/tg-panel/.env` | `LLM_API_KEY`, провайдер OpenRouter |
| Ключ туннеля Латвия | `/opt/tunnel-lv/config.json` | VLESS/Reality: `id` и `publicKey` |
| Доступ к серверу | SSH-ключ на компьютере владельца | пароль по SSH выключен |
| Сессии Telegram | `<профиль>/sessions/*.session` | файл = полный доступ к аккаунту, обращаться как с паролем |
| Адрес Google-таблицы лидов | `<профиль>/leads-sheet.txt` | ссылка с `api_key`; после 16.10 панель его не читает |

Сводку путей владелец может выгрузить одной командой — см. `/root/ПЕРЕДАЧА.txt`
(файл только для root, в репозиторий не попадает).

## 7. Выкладка

```bash
cd ~/Projects/tg-check && bash deploy/push.sh root@46.16.15.238 --code-only
```

Копирует **только код**: сессии, реестр, базы, `.env` и прочие данные остаются
на сервере нетронутыми. Служба перезапускается. Перед этим `--code-only` ждёт
до 10 минут, пока не будет идущих задач (не ждать — `--force`).

Если под рукой только консоль сервера (Termius), то же самое — прямо там, из
свежей копии репозитория:

```bash
rm -rf /root/tg-check-src && git clone -q -b web-refactor https://github.com/zahar-pr/tg-check /root/tg-check-src
bash /root/tg-check-src/deploy/push.sh --here --code-only
```

Если на сервере стоит код новее, чем на GitHub (правили и выкладывали мимо
репозитория), `push.sh` его затрёт. Тогда сначала слить:
`bash /root/tg-check-src/deploy/merge-here.sh` — основа серверный код,
сверху изменения ветки, проверки (синтаксис, тесты обогащения, запуск панели);
живую панель не трогает. Ставить — командой, которую он напечатает в конце.
Правки с сервера он складывает в `/root/tg-merge/owner-changes.tgz` — их стоит
отправить на GitHub. Повторная выкладка так же — с `--base <коммит прошлой
выкладки>`: наложится только то, что изменилось с неё. Первая выкладка
обогащения так была с ffc2be9 (22.10).

Три правила, выученных на практике:

1. **Выкладывать в паузе.** Перезапуск обрывает идущие задачи. Проверить:
   `pgrep -u tgpanel -f 'python.*\.py' | wc -l` должно быть `0`.
2. **Файлы интерфейса можно класть без перезапуска.** `web/*` читаются с диска
   на каждый запрос — `scp` достаточно, служба не трогается, работа не рвётся.
3. **Браузер кеширует.** Поправил `app.js` или `app.css` — подними версию
   `?v=rNN` в `web/index.html` и `web/profiles.html`.

После выкладки сверить: `md5sum` на сервере против `md5 -q` локально.

## 8. Ограничения Telegram и как панель с ними живёт

* **SpamBot.** Раз в сутки аккаунт спрашивает, нет ли ограничений. Временное —
  карантин до даты снятия, аккаунт возвращается сам. Бессрочное — выбывает.
* **Квота на добавление контактов.** Telegram не говорит, когда она вернётся.
  Панель ждёт 12 часов и пробует **один** номер; прошёл — снимает ожидание.
  Реальный потолок у этих аккаунтов — 20–30 добавлений в сутки.
* **Флуд.** `FloodWait` — пауза ровно на столько, сколько просит Telegram.
  `PEER_FLOOD` — аккаунт выбывает до разбора руками.
* **Рабочее время** для действий с людьми: 06:00–24:00 по Екатеринбургу.
  Сервер живёт по UTC.
* **Имя человека** Telegram отдаёт, только если он не в контактах.

## 9. Грабли

* Окна `prompt/confirm/alert` в интерфейсе замораживают страницу.
* `accounts.json` пишут и панель, и Python-задачи — править руками только при
  остановленной панели.
* **Не переписывай CSV питоновским `csv.writer`**: он ставит окончания строк
  `\r\n`, и колонка в шапке получает невидимый возврат каретки. Читалка теперь
  это терпит, но данные лучше не портить.
* Один мобильный прокси на 19 аккаунтов — всё идёт по очереди, каждому
  достаётся мало времени. Стоит второй прокси.
* Запуск скрипта мимо панели конкурирует с ней за сессию: `database is locked`.
  Запускай задачи через панель либо убедись, что она свободна.
* Время: сервер UTC, суточные лимиты считаются по скользящим 24 часам,
  рабочее время — по Екатеринбургу.
