# Где остановились (22.10) — для сессии, которая работает с сервером

Сервер: `ssh root@46.16.15.238` (вход по ключу). Панель — служба `tg-panel`,
код в `/opt/tg-panel`, адрес https://bqa.egor-kochnev.ru. Второй профиль —
`/opt/tg-panel/profiles/vtoroy` (свои аккаунты и данные, код общий).
Задачи панели работают от пользователя `tgpanel`: запуская что-то руками,
делай это через `runuser -u tgpanel -- env TG_PANEL_DIR=… venv-tg/bin/python …`,
иначе в папках профиля появятся файлы root, которые панель не сможет писать.

## Правила

- Секреты не выводить и не пересказывать: `.env`, `asocks.json`, `*.session`,
  `/root/ПЕРЕДАЧА.txt`, `/root/*.creds`, строки прокси с паролями.
- Это живая рассылка. Перезапуск — только через `deploy/push.sh --code-only`
  (он сам ждёт паузы в задачах); владельца предупреждать.
- Код на сервере новее GitHub: владелец правил его мимо репозитория. Поэтому
  выкладка — только через `deploy/merge-here.sh` (основа — серверный код,
  сверху разница ветки). Обычный `push.sh` с компьютера его правки затрёт,
  пока они не попали в git (см. ниже).
- Репозиторий ПУБЛИЧНЫЙ. Ничего с сервера не коммитить, не проверив на
  секреты; новые скрипты владельца — только с его согласия.

## Что выложено

Обогащение (вкладка «Лиды», автопилот, профили лидов) + правки владельца.
Последняя выкладка — через merge-here; база для следующей —
коммит, выложенный последним (проверить: `grep -c "Читатели" /opt/tg-panel/web/app.js`
— больше 0 значит 3c8edb1, иначе 2995f7c). Следующая выкладка на сервере:

    cd /root && rm -rf tg-check-src && mkdir tg-check-src \
      && curl -sL https://codeload.github.com/zahar-pr/tg-check/tar.gz/<НОВЫЙ_КОММИТ> \
         | tar xz -C tg-check-src --strip-components=1 \
      && bash tg-check-src/deploy/merge-here.sh --base <ВЫЛОЖЕННЫЙ_КОММИТ>
    # «5/5 Всё чисто» → bash /root/tg-merge/work/deploy/push.sh --here --code-only

## Открытые вопросы

1. **Прокси второго профиля.** У всех 6 аккаунтов vtoroy прокси отвечают
   `404 Not Found` (`proxy-check.py`); читатель Ниша2 4761 (n4) падал в
   enrich-find с `ConnectionError`. Нужен рабочий прокси хотя бы одному
   читателю (решает владелец) — или читатель из профиля, где прокси живые.
   Дальше проверить автопилот вживую: поиск чатов → чтение → разбор → профили.
2. **Правки владельца — в git.** merge-here сложил их в
   `/root/tg-merge/owner-changes.tgz`: файлы, которые на сервере отличаются
   от базы последней выкладки (это его правки поверх нашей ветки), и его
   новые скрипты (find_discuss.py, lead-watch.sh, biz_*.sh, warmup_watch.py,
   reclean.py, incoming/*.py). Как перенести: ветка от коммита-базы, файлы из
   архива поверх, проверить на секреты, коммит «правки владельца с сервера»,
   слить в web-refactor. Новые скрипты — только если владелец согласен (в
   incoming/ могут быть данные). После этого выкладка снова возможна обычным
   `push.sh` с компьютера.
3. **ГигаЧат для «Лидов».** Ключ — `GIGACHAT_CREDENTIALS=…` в `/opt/tg-panel/.env`
   (у профиля со своим `.env` — и там), сертификат Минцифры —
   `/opt/tg-panel/russian_trusted_root_ca.pem`. Проверка:
   `runuser -u tgpanel -- venv-tg/bin/python llm.py --gigachat` (вход, модели,
   остаток токенов, пробный ответ). Без ключа обогащение работает на общей модели.
4. Общая модель на сервере — `deepseek/deepseek-v4-flash` (OpenRouter), многословная:
   ключевики берутся порциями по 60 (enrich-find.gather). Разбор лидов на ней
   работает хорошо (проверено владельцем).

Тесты (нужен Telethon в venv): `python tests/sandbox/enrich_test.py`,
`node tests/sandbox/enrich_sched_test.mjs`.
